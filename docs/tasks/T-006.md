# T-006: Identity with Dapper stores

- Depends on: T-002, T-004
- Developer model: sonnet
- Test model: sonnet
- Review: sonnet
- Human gate: no

## Goal
Connect ASP.NET Core Identity to SQL Server through Dapper with no EF.

## Scope
- Add `AppUser`, `AppRole`, and Dapper stores: user, password, email, security stamp, lockout, role.
- Register with `AddIdentityCore`, roles, sign-in manager, default token providers.
- Set password, lockout, token and cookie options from PLAN section 6, including PBKDF2 iterations.

## Acceptance criteria
- [ ] Store tests cover create, update, find by normalized e-mail, roles, lockout and stamp changes.
- [ ] Stale `ConcurrencyStamp` update fails.
- [ ] Password hash uses at least 210,000 iterations.
- [ ] No package reference to Entity Framework exists.
- [ ] All SQL is parameterized.

## Out of scope
- UI pages.

## Always applies
`CLAUDE.md` rules, `docs/PLAN.md`, and `dotnet build -warnaserror` plus `dotnet test` passing.
